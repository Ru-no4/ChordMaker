# ChrodMaker

任意の音程を選んで和音を作り、コードを判定し、DAW風UIで再生・編集する
**作曲支援兼音楽理論学習ツール**。[要件定義.md](要件定義.md) の初版に基づく実装。

## セットアップ

```bash
npm install
```

```bash
npm run dev
```

開発サーバは http://localhost:5173 で起動します。本番ビルドは `npm run build`、
型チェックのみは `npx tsc -b`。

## 技術構成

- **Vite + React 18 + TypeScript**
- **Tone.js** — Transport の tick 基準でスケジューリング（再生中の BPM 変更でもズレない）
- **smplr** — サンプル音源（Splendid Grand Piano / GM 128音色）
- **Zustand** — プロジェクト状態。再生位置だけは別ストアに分離して 60fps 更新でも
  タイムライン全体を再描画しない構成

## 使い方

### 4つのツール

**すべての操作はツールだけで到達できます。** 修飾キー・右クリック・ダブルクリックは
デスクトップの近道であって、唯一の手段にはしていません（タッチで機能が欠けないため）。

| | 空きをドラッグ | 要素をタップ | 要素をドラッグ | 右端をドラッグ |
| --- | --- | --- | --- | --- |
| **鉛筆** `1` | （タップで配置 / 追加） | 選択 | 移動 | 長さ変更 |
| **範囲選択** `2` | 矩形で複数選択 | 選択をトグル | 選択全体を移動 | 選択全体を同量リサイズ |
| **消しゴム** `3` | なぞった分をまとめて削除 | 削除 | （なぞり削除） | — |
| **手** `4` | ビューをスクロール | — | ビューをスクロール | — |

鉛筆はピアノロールの空きタップでノート配置（そのままドラッグで長さ決め）、
コードトラックの空きタップでブロック追加。ルーラーはドラッグで再生位置をスクラブ、
鍵盤タップで単音プレビュー、候補チップのタップで和音を確定します。

**選択・配置・削除・移動はブロックを跨いで働きます。** 矩形選択で複数小節のノートを
まとめて掴め、移動は選択全体で共通の差分になります。ノートは移動先の絶対位置を覆う
ブロックへ自動で属し直すので、小節をまたいだ移動やコピーも自由に行えます
（属せるブロックが無い空白へは、最寄りのブロックの内側へ寄せます）。

ドラッグ中に表示端へポインタを寄せると自動でスクロールします（ルーラーのスクラブ、
ノートの移動・リサイズ、矩形選択）。

### コピー & 貼り付け

選択中のノート、またはコードブロックを `Ctrl`(`Cmd`)+`C` でコピーし、`Ctrl`(`Cmd`)+`V` で
再生ヘッドの位置を始点に貼り付けます。`Ctrl`(`Cmd`)+ドラッグでも複製でき、この場合は
離した位置がそのまま貼り付け先になります。

### デスクトップの近道

`Shift`+ドラッグ = 一時的に矩形選択 / `Shift`+クリック = 選択に追加・解除 /
`Ctrl`(`Cmd`)+ドラッグ = 選択中のノート / コードブロックを複製して、離した位置へ配置 /
中ボタンドラッグ = パン / ダブルクリック・右クリック = ノート / コードブロックを削除 /
`Ctrl`(`Cmd`)+ホイール = 横方向の拡大縮小（`Shift` 併用で縦）

### 保存 / 読み込み

コントロールバー左側の保存・開くボタンで、作成したコードトラック・ピアノロールを
ファイルに書き出し／読み込めます。中身は JSON で、拡張子は独自の `.chrd`。
サーバーや DB は使わず、ブラウザのダウンロードとファイル選択だけで完結するので、
データは一切外部へ送信されません。テンポ・拍子・小節数・コード解像度・
クオンタイズ・音源・音量・全コードブロック（構成音を含む）を保存します。
表示倍率や選択状態などの一時的な UI 状態は保存対象外です。

壊れたファイルや別アプリのファイルを読み込もうとした場合はエラー表示に留まり、
現在編集中の内容は変わりません。正常に読み込めた場合、コード・小節数・拍子は
`Ctrl+Z` で読み込み前の状態に戻せます（テンポなどの設定値は他の操作と同様、
Undo の対象外です）。

### 音源

コントロールバーの「音源」から切り替えられます。

- **合成音** — 既定。ダウンロード不要で即鳴ります
- **Splendid Grand Piano** — Steinway のマルチサンプル（4ベロシティ）。質は最良ですが
  初回に 200 個以上のサンプルを取得するため読み込みに少し時間がかかります
- **GM 128音色** — ピアノ・エレピ・オルガン・ギター・弦・パッドなどをよく使う順に並べ、
  残りは「すべての音色」にまとめてあります。1音色につき1ファイルなので読み込みは速い

読み込み中は「読込中」と表示され、その間も合成音で鳴り続けるので操作は止まりません。
一度読み込んだサンプルはブラウザにキャッシュされます。オフラインで使う場合は合成音を選んでください。

### 表示倍率

コードトラックとピアノロール、それぞれの右下（ピアノロールは右端に縦、下端に横）に
ズームスライダーがあります（Cubase のプロジェクト窓・キーエディタの配置を参考）。
横（`H`）は時間軸（1拍の幅）、縦（`V`）は音程の行高とコードブロックの高さに効きます。
コードトラックとピアノロールは同じ表示倍率を共有するので、どちらで操作しても両方に反映されます。
`Ctrl+ホイール`（横）/ `Ctrl+Shift+ホイール`（縦）でも操作できます。

### キーボード

`1`〜`4` ツール切替、`Ctrl+Z` 元に戻す、`Ctrl+Y`（`Ctrl+Shift+Z`）やり直す、
`Space` 再生/一時停止、`Esc` 停止、
`Del` 選択ノートを削除（未選択ならブロック削除）、`Ctrl+A` ブロック内全ノート選択、
`P` ピアノロール開閉、`?` / `F1` 操作一覧。

画面右上の `?` ボタンからも全操作の一覧を開けます。

### 再生ヘッドの追従（FOLLOW）

再生中、再生ヘッドが表示領域の中央に来たところから画面が自動で流れます。
中央より左にいる間はスクロールせずヘッドだけが進み、
最初から中央より右にある場合は一度中央へ寄せてから追従します。
手動でスクロールしながら聴きたいときは `FOLLOW` を切ってください。

### 元に戻す / やり直す

ノート・コードブロックの編集と、拍子・小節数の変更が対象です。
ドラッグは掴んでから離すまでが1操作にまとまるので、`Ctrl+Z` 一回で
ドラッグ前の状態へ戻ります。ツール選択・表示倍率・再生状態・選択状態は履歴に含めません。

## 実装のポイント

### コード判定 (`src/lib/theory.ts`)

テンプレート総当たりではなく、**ルート候補ごとの構造解析**でコードを命名する。
12個のルート候補それぞれについてインターバル集合を 3rd / 5th / 7th / テンション に
分解し、命名の自然さをスコア化して最良の解釈を選ぶ。

- 13th までの拡張コード（`C13(#11)`、`Cmaj13`、`Cm11` など）
- オルタードテンション（`C7(b9)`、`C7(#9)`、`C7(b13)` など）
- 分数コードは2通りの経路で判定する
  - 転回形として: `C/E`、`C/G`（ベースが和音構成音）
  - 上部構造+ベースとして: `F/G`、`Dm7/G`（ベースが非構成音）
- 単音・2音は**候補提示モード**。ベース音をルートとする解釈を優先しつつ、
  「その音が3rd/5thになる別ルートの和音」も残す
- 第一候補から一定スコア差以内の解釈は「別解釈」として併記

コードタイプは Major / Minor / Dominant / Diminished / Suspended / Tension の
6分類に色分けされ、コードブロックとピアノロールのノートで共有される
（`src/lib/colors.ts`）。分数コードのベース音は、ルートがシャープ系（G/D/A/E/B/F#）か
フラット系かで綴りを切り替える（A メジャーの第3音は `Db` ではなく `C#`）。

### 小節内の複数コード判定 (`src/lib/segmentation.ts`)

1つのコードブロックの中でコードを弾き分けても、全ノートを混ぜて判定すると
意味のない和音名になる（`Am7` + `A` → `A7(#9)`）。そこでブロックを時間で区切り、
**セグメント**ごとに判定してコードトラックに並べて表示する。
ノートデータには手を入れない非破壊方式なので、ノートを動かせば区切りも追従する。

判定は「拍グリッドの窓 → 窓ごとに判定 → 結合」の3段構成:

1. **窓** — コントロールバーの `CHORD` で刻む。**小節を何分割するか**で指定し、
   小節 / 1/2 / 1/3 / 1/4 / 1/6 / 1/8 から選ぶ（既定 1/4）。
   全音符基準ではなく小節基準なのは、6/8 のような複合拍子と噛み合わせるため
   （6/8 の1小節は 24 step なので、全音符の 1/4 = 8 step では 3/8 のコードを割り切れず、
   1小節が 2/8 ずつ3つに割れてしまう）。小節基準なら 6/8 の 1/2 がちょうど 3/8 になり、
   3分割・6分割で三連系も扱える。割り切れない窓長（4/4 の 1/3 = 32/3 step）は
   小数のまま計算する
2. **判定音の選別** — 窓長の 50% 以上鳴っているノートが3つ以上あれば、それだけで判定する。
   伸ばした和音の上を走る短い経過音が判定を汚さない
3. **結合** — 同じコードが続く窓はラベルを保ったまま結合。確信の持てない窓は隣に吸収し、
   確定コードが1つも出なければ全体の union を再判定する（＝疎なノートでも従来通り候補提示に戻る）

| ノートの置き方 | 結果 |
| --- | --- |
| 前半 Am7 / 後半 A | `Am7` `A/C#` の2セグメント |
| 1拍内のアルペジオ | 窓内で集約されて1コード |
| 全音符の和音＋16分の経過音 | 経過音を除いた和音のみ |
| 疎に1〜2音だけ | 1セグメントに退化して候補提示 |
| 6/8 で 3/8 ずつのコード | `1/2` で 3/8 ちょうどの2セグメント |

### 時間軸 (`src/lib/grid.ts`)

内部の最小単位は **32分音符 (step)**。1拍あたりの step 数は拍子の分母から決まる
（4/4 なら 8 step、6/8 なら 4 step）。1拍の表示幅は 96px 固定。
クオンタイズ 1/4・1/8・1/16・1/32 と SNAP ON/OFF に対応。

### 再生 (`src/lib/audio.ts`)

音源は2系統を `AudioEngine` の内側に持ち、同じ AudioContext・同じエフェクト経路に流す。

- **内蔵シンセ**（Tone.PolySynth）— ダウンロード不要で即鳴る。既定であり、
  サンプル読み込み中の代替でもある
- **サンプル音源**（[smplr](https://github.com/danigb/smplr)）— Splendid Grand Piano
  （Steinway・4ベロシティ）と GM 128音色（MusyngKite）

`Soundfont` / `SplendidGrandPiano` はネイティブの `AudioNode` しか受け取らないので、
中継用の `GainNode` を作って `Tone.connect()` でエフェクト経路へ差し込んでいる。
発音は `AudioEngine.trigger()` に集約してあり、`Tone.Part` のコールバックが渡す
絶対時刻をそのまま smplr の `time` に渡せる（smplr の `time` も AudioContext の絶対秒）。
音色を切り替えても `Tone.Part` は組み直さない。

読み込みは非同期で、終わるまでは内蔵シンセのまま鳴るので操作は止まらない。
読み込み中に別の音色へ切り替えた場合は、後から届いたほうを破棄する。
失敗しても内蔵シンセへフォールバックする。

停止・シークでは `silenceNow()` で鳴っている音を即座に切る。
`releaseAll()` だけだと通常のリリース（1秒強）ぶん余韻が残って
「停止したのに鳴り続けている」ように聞こえるため、
リリースを一時的に詰めてから解放し、直後に元の値へ戻している。

## コンポーネント構造

```
App
├─ ControlBar        BPM / 拍子 / 小節数 / ループ / 再生・停止 / Chord / Quantize / Snap
│  ├─ PositionReadout
│  └─ ToolStrip      鉛筆 / 範囲選択 / 消しゴム / 手
├─ ChordInspector    セグメント切替・判定結果・構成音・別解釈・候補提示・凡例
├─ workspace
│  ├─ ChordTimeline  ルーラー + コードトラック（高さ60px のブロック、32分グリッド）
│  │  ├─ ChordBlock  入れ物。色と和音名はセグメントが持つ
│  │  │  └─ ChordSegment
│  │  └─ Playhead
│  └─ PianoRoll      折りたたみ式、C2〜C5、左に120px の鍵盤
│     ├─ Keyboard
│     ├─ Note        表示専用
│     └─ Playhead
└─ ShortcutHelp      全操作の一覧（? / F1）
```

タイムラインとピアノロールは横スクロールを同期する（`src/lib/scrollSync.ts`）。

ピアノロールのポインタ操作は `src/hooks/usePianoRollGesture.ts` に集約している。
ノートごとにハンドラを付けず、グリッド1枚で `data-note-id` / `data-note-handle` を見て
イベント委譲するため、ツールごとの分岐が1箇所にまとまる。
複数ノートのドラッグは差分を累積せず、開始時のスナップショットから毎回絶対値を計算する
（累積すると範囲端に当たったノートだけ取り残されて選択が崩れる）。
自動スクロール中も同じ計算を回すため、スクロール量を差分に加算している。

端での自動スクロールの速度計算は `src/lib/edgeScroll.ts` に純粋関数として切り出してある
（requestAnimationFrame が動かない環境でも検証できるようにするため）。

## タッチ操作について

要件の「タブレット・スマホは縮小表示」に対し、操作面でも次を担保している。

- ポインタイベントに統一し、`e.pointerType` でマウス / 指を区別。
  タップ判定のしきい値も分けている（マウス 4px / 指 10px、`src/lib/pointer.ts`）
- `touch-action` はツールごとに切り替える。背景ドラッグを使わない鉛筆・手では
  ブラウザ標準のスクロールを残し、範囲選択・消しゴムでは無効化したうえで
  **2本指ドラッグをパンに割り当てる**（どのツール中でも有効）
- ホバー依存を排除。リサイズハンドルは選択中は常時表示し、
  `@media (hover: none)` では見た目を変えずに当たり判定だけ広げる
- ツールボタンはタッチ環境で 44px 四方を確保
- 削除はホバーや右クリックに頼らず消しゴムツールを正規手段とする

## 今後の拡張（未実装）

要件定義 6章の項目。ライトテーマ、コード進行の保存・読み込み、
MIDI 書き出し、コード進行の自動生成、ボイシング提案。

なお UJAM「Virtual Pianist VOGUE」は VST3/AU プラグインのため、
ブラウザから読み込む手段が原理的に存在しません（ライセンス以前の制約）。
さらに音色を鳴らすだけでなく伴奏パターンを生成するプラグインなので、
本アプリの「置いたノートを鳴らす」用途とも役割が異なります。
より質の高い音を同梱したい場合は、CC0 の
[VCSL](https://github.com/sgossner/VCSL) / VSCO 2 CE を自前で持つか、
[spessasynth_lib](https://github.com/spessasus/spessasynth_lib) で任意の
SoundFont(.sf2) を読み込めるようにする方向になります。
